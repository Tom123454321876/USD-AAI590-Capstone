# Eye Style capstone HTTP bridge (demo only)
Add this backend directory through a reviewed feature branch. Existing notebooks are unchanged. This is a proposed adapter, not a deployed or end-to-end tested service.

Cloud Build Dockerfile: `/backend/Dockerfile`; branch `^main$` after review. Cloud Run runtime identity: `eye-style-capstone-backend@eye-style-optometry---ai.iam.gserviceaccount.com`. Keep Cloud Run IAM authentication enabled for initial tests. Do not expose public access until application authorization and frontend integration are verified. Firebase ID tokens alone do not satisfy Cloud Run IAM; initial private tests need a Cloud Run invoker identity token separately (X-Serverless-Authorization) plus Firebase ID token in Authorization.

Environment: `FIREBASE_PROJECT_ID=eye-style-optometry---ai`; `DATABRICKS_SERVING_URL` = verified custom serving endpoint invocation URL; `ALLOWED_ORIGINS` = comma-separated exact Firebase Hosting origins (no wildcard); `DATABRICKS_TOKEN` = Secret Manager reference `databricks-serving-token`, version 1. Never commit tokens. Runtime uses application default credentials; no JSON key needed. No Firestore access is used in this adapter. A trusted Firebase administrator must set the `role` custom claim for approved demo users; role is never accepted from request JSON. Existing frontend role storage was not supplied, so custom claims are a design choice requiring integration.

## Upstream serving contract — not present in uploaded repository
The Databricks endpoint must be a custom model endpoint exposing the existing initialized notebook functions, NOT a generic LLM endpoint or the no-show model alone. Package and initialize required synthetic data, model, RAG and gateway dependencies in the serving environment; notebook globals and private volume paths are not automatically available to a model-serving process. Do not copy vendor specs or live data into public GitHub. A proposed MLflow dataframe request contains one row with action, question, workflow, authenticated_role, authenticated_subject. Dispatch `chat` to `eye_style_deployment_chat(question, workflow, authenticated_role, authenticated_subject)`, `dashboard` to `eye_style_dashboard(authenticated_role, authenticated_subject)`, and `capabilities` to `eye_style_deployment_capabilities(authenticated_role, authenticated_subject)`. Return one JSON string or object in `predictions`. The bridge checks demo mode and role, plus action-specific fields. Confirm the actual endpoint schema before deployment; change adapter if necessary.

Routes: GET /health (process only, not end-to-end readiness), POST /chat with JSON question and workflow, GET /dashboard, GET /capabilities. All except /health require Firebase ID token. Use synthetic data only. Before public access, verify denied unauthenticated and unauthorized requests, valid responses for all 4 workflows, strict frontend origins, role provisioning and rate limiting. Test upstream with authorized credentials without displaying tokens. No live connection or automatic patient actions are intended.
